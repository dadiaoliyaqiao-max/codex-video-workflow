给第一次使用的同事

从素材到成片，
按这份教程走。

安装一次工具，给每条视频建独立项目。Codex 负责整理素材、制定方案、剪辑和导出；你负责提供要求，并在三个关键版本上确认。

Windows公开仓库，无需 GitHub 账号单文件 HTML，可离线打开适用于短视频和系列视频
从安装开始 ↓直接看制作流程
01

先看全流程

你不需要自己逐条敲剪辑命令。按顺序提供素材、看成果、提修改或确认即可。

1

安装环境

复制一行命令。安装器下载流程包，检查并准备剪辑、转写、动效和封面工具。

2

准备每条片的素材

放入独立项目目录，告诉 Codex 开头、结尾、口播、参考片、封面要求及禁用素材。

3

看三个实际成果

依次确认剪辑思路、正式分镜、完整预览连同真实封面。需要调整就直接指出。

4

领取成片和工程

拿到 MP4、封面、字幕、可继续修改的 EDL 和设计源，以及必要的音乐字体署名。

先记住这条原则

“采用这套流程”只表示工作方式确定，并不等于任何新视频已经审过。每条视频有自己的素材、需求和确认记录。

02

第一次使用：一键安装

先准备 Windows PowerShell、网络和已登录的 Codex 桌面应用。GitHub 不用注册。

在 PowerShell 粘贴这一整行，按回车

PowerShell · 一行安装与更新
$setup = Join-Path $env:TEMP 'codex-video-workflow-bootstrap.ps1'; Invoke-WebRequest 'https://raw.githubusercontent.com/dadiaoliyaqiao-max/codex-video-workflow/main/scripts/bootstrap-windows.ps1' -OutFile $setup -UseBasicParsing; powershell.exe -NoProfile -ExecutionPolicy Bypass -File $setup
下载到哪里？默认在“文档/CodexVideoWorkflow/codex-video-workflow-main”；以终端最后打印的完整路径为准。
安装什么？缺失的 Node.js、Python、FFmpeg、Git、CMake；本地 Pillow、Hypit、HyperFrames、Puppeteer、浏览器和中文转写准备。
怎么看结果？打开 install-logs/install-report.json，确认状态为 complete，且关键步骤没有失败或意外跳过。
首次安装可能需要一些时间

浏览器和转写模型需要下载；WinGet 可能弹出系统管理员确认。安装失败时看报告中的错误，处理后重复运行同一行。以后也可用同一行更新流程代码，原有 runtime.local.json 和 剪辑项目/ 会保留。

这条命令会从公开 GitHub 仓库下载并运行脚本。运行前可先查看启动脚本源码。安装器不会安装 Codex 桌面应用或替你登录账号。

03

准备一条视频的素材

每条视频单独放一个项目。原始视频和录音保持不变；剪辑生成的文件留在该项目的 edit/ 中。

推荐目录

剪辑项目/ └─ 项目名/ ├─ 素材/ 原视频、口播录音、片尾等 ├─ 参考视频/ 可选：想参照的剪辑样片 ├─ 封面参考/ 可选：同系列版式示例 └─ edit/ Codex 建档后生成，不手动改原片

素材已在别处也可以，给 Codex 完整路径即可。不要把另一条视频的素材或确认记录混进来。

开工前告诉 Codex

0 / 6 已准备

没有的素材不用硬凑

不是每条片都要有参考视频、真人照片或品牌片尾。把“没有”告诉 Codex 即可。空间镜头和细节镜头按口播内容选用，也不需要把所有素材都塞进成片。

04

在 Codex 中开工

将安装结束时显示的流程目录设为 Codex 的工作目录，开启新对话。复制下方文字，替换方括号中的内容。

新视频：发这段指令

发给 Codex · 新项目
先读本目录 AGENTS.md 和 workflow-kit/codex-video-workflow/SKILL.md。
请为【项目名】建立独立的剪辑项目，素材在【完整路径】。
本期用途和要求：【平台、画幅、时长、帧率、标题、封面、配乐、字幕、参考视频、必留与禁用内容】。
先盘点素材和声音，给我剪辑思路；按思路、正式分镜、完整预览＋实际封面三个确认点推进。
请告诉我当前缺少什么，以及下一步我需要看什么。

项目名尽量具体，例如“厨房改造案例_2026-11”。如果尚未提供全部要求，先写已有信息；Codex 会集中提出真正影响方案的问题。

继续一条做过的片

在新对话里告诉 Codex 原项目目录，并要求它先运行 context 读取当前 brief、EDL 和状态。不要重新初始化或套用另一条片的审批。

发给 Codex · 续作
继续项目【项目完整路径】。先读 AGENTS.md，并运行工作流工具.cmd context --project "【项目完整路径】"；以本片当前 brief、EDL 和 workflow/state 为准。我的这轮修改是：【具体修改】。只重做受影响部分，并告诉我需要重新确认的成果。
05

一条视频怎样做出来

下面是制作时真正的先后顺序。黄色“确认点”表示你需要看到实际成果后明确回复。

0

建档与素材盘点

Codex 会做

读取本片要求；用 FFprobe 记录素材路径、指纹、时长、画幅、帧率和音轨；查看空间、细节、人物及首尾素材；裁掉不稳定的起落镜。口播做真实转写和词时间校对。

你要做

确认文件有无缺漏，指出必留、禁用和不适合的画面。参考片只用于学习做法，不会自动替代本片素材。

内部入口：init → inventory；有参考视频时再做 reference。产物是 brief、素材索引、截图和声音证据。
1

剪辑思路

确认点 1
Codex 会做

提出开场、正文、结尾的叙事顺序，说明选哪些镜头、为什么选；同时确定调色、字幕、主字、转场、音乐、音效和封面方向。新风格附 6–8 秒带声音代表样段。

你要做

看逻辑、节奏、画面选择和风格。想改就说具体哪里；满意时明确回复“确认这版剪辑思路”。

确认只对应你实际看过的这一版思路，不代表分镜或成片已通过。
2

正式分镜与剪辑表

确认点 2
Codex 会做

给每镜标素材、原片入出点、成片时间、真实截图、口播/字幕、主字与音效时刻、转场和调色。检查空间与细节是否匹配，是否出现重复画面或提前出字。

你要做

逐段核对内容和镜头。特别看开头、结尾、品牌片尾、重点词对应画面。满意时明确确认这版分镜。

内部入口：storyboard。产物包含 storyboard.html/json 与 edl.json。
3

正式制作

Codex 会做

按已确认分镜剪视频、调色、制作文字和转场；用真实词时间排字幕与重点字；分层混合口播、配乐和音效；制作可编辑的实际封面。目标 60 fps 等数值仅在本片明确提出时执行。

你要做

若出现新素材、新标题或新要求，及时发给 Codex。不要把上一条视频的色值、曲目或人物视为本片默认。

普通剪辑主要由 FFmpeg 完成；复杂字效按需用 HyperFrames 或 Remotion，有参考片时按需用 Hypit。
4

完整预览＋实际封面

确认点 3
Codex 会做

保留 1920 长边的最终质量内部母版，并生成 1280 长边完整审片版；做一次集中技术、画面和声音复核，展示真实 MP4 与 PNG/JPG 封面。

你要做

从头到尾观看并听关键段，核对字幕、配乐、转场、封面、安全区和片尾。修改就逐条指出；满意时明确确认这版预览与封面。

内部入口：render-preview。没有看到真实预览和封面，就不算完成这个确认点。
5

最终交付

Codex 会做

核对批准版本、母版和检查记录，复用相同母版交付；归档最终 MP4、封面、字幕、EDL、设计源及必要署名，并验证文件链接和依赖。

你要做

下载或复制完整交付目录，检查视频能播放、封面与成片属于同一版，再交给发布同事。

内部入口：render-final；发布到平台是单独操作，未经授权不会自动上传。
06

审片时看什么

完整预览要看整条，不只看截图。你可以用下面的清单逐项检查。

画面与文字

0 / 6 已检查

声音、封面与文件

0 / 6 已检查

勾选状态仅保存在你当前浏览器，不会上传。系列封面安全区以本片要求为准；不要把某条片的坐标直接套给所有视频。

07

交付与后续修改

交付的是一套可继续修改的文件，而不只是一个 MP4。

应拿到的文件

  • 最终视频 MP4，以及同版本封面 PNG/JPG
  • 可单独使用的字幕 SRT/ASS
  • 剪辑表 EDL、封面/动效设计源与工程入口
  • 必要的音乐、字体和其他素材署名
  • 交付清单，写清文件路径及外部素材依赖

EDL 是可追溯的 JSON 剪辑数据，不是剪映、Premiere 或 DaVinci Resolve 的原生工程。

修改时这样说更快

给出位置、问题和想要的结果。例如：

  • “18 秒处主字比口播早，等说到‘收口’才出现。”
  • “封面文字整体下移，但保持原字号和排版。”
  • “配乐再轻快一些，音效比现在明显一点。”
  • “这两个话题用了同一空间画面，换掉其中一镜。”

Codex 会按影响范围修改：封面改动复用视频，音量改动复用画面，单组动效只重做该组；变更后检查受影响的确认。

确实不需要再审时

明确写“这条视频按当前要求直接导出终稿，不再给我审”。这项授权只对你指定的这一条片和这一轮范围有效；技术检查、完整性检查与交付清单仍须完成。不要让 Codex 把未看过的预览记成已确认。

08

每个工具分别做什么

安装了某个工具，不表示每条视频都会用它。实际使用情况以本片记录的命令、输入和产物为准。

工具 / 项目作用什么时候用
Codex
协作入口		理解需求、选镜、组织分镜、检查结果并调用本地工具。整个流程；桌面应用与账号需自行准备。
workflow-kit
仓库自带		项目建档、素材索引、EDL、阶段状态、确认和缓存检查。每条片。入口是 工作流工具.cmd。
FFprobe / FFmpeg
常规剪辑		探测素材、抽帧、切剪、调色、字幕、混音、编码和完整解码检查。大多数视频；由安装器检查或安装。
Pillow
图像处理		图片检查、截图索引及辅助图像处理。盘点、分镜或封面辅助。
HyperFrames + 本地 Whisper
按内容启用		中文口播转写准备；复杂文字与图形动效可用 HyperFrames。有口播或需要复杂字效时；词时间仍要对照真实声音。
Hypit
参考片时		拆解参考视频的镜头边界、时间码和画面变化。用户给参考片时；无参考片可跳过。
Puppeteer + Chrome
封面排版		把可编辑的 HTML/CSS 封面准确截图成 PNG/JPG。需要精确排版封面时；不负责替换真人或自动抠像。
Remotion
备选		有现成 React 模板或复杂参数化动画时可选。按项目需要和许可条件单独配置；默认安装器不装。
素材和工具分开理解

流程包不包含别人的原视频、真人照片、已批准成片、账号或密钥。工具自动安装成功也不代表某条新片已转写、审美通过或能直接发布。

09

给技术同事的命令参考

这些是 Codex 在合适阶段调用的入口，不是让人一次性从上到下全部运行。

在流程包根目录运行
.\工作流工具.cmd doctor
.\工作流工具.cmd init --project "剪辑项目/新视频" --name "新视频"
.\工作流工具.cmd context --project "剪辑项目/新视频"
.\工作流工具.cmd inventory --project "剪辑项目/新视频"
# 有参考视频且 Hypit 就绪时：
.\工作流工具.cmd reference --project "剪辑项目/新视频"
# 用户看过并明确确认剪辑思路之后：
.\工作流工具.cmd approve --project "剪辑项目/新视频" --stage strategy --message "用户实际原文"
.\工作流工具.cmd storyboard --project "剪辑项目/新视频"
# 用户看过并明确确认分镜之后：
.\工作流工具.cmd approve --project "剪辑项目/新视频" --stage storyboard --message "用户实际原文"
.\工作流工具.cmd render-preview --project "剪辑项目/新视频"
# 用户看过完整预览和真实封面并明确确认之后：
.\工作流工具.cmd approve --project "剪辑项目/新视频" --stage preview --message "用户实际原文"
.\工作流工具.cmd render-final --project "剪辑项目/新视频"
不要提前执行 approve

approve 只能记录用户对当前实际成果的明确确认。策略通过不等于分镜通过，分镜通过不等于完整视频通过；测试项目的确认也不能转用到真实视频。

查看项目进度：.\工作流工具.cmd status --project "剪辑项目/新视频"；继续项目：context；查询命令耗时：metrics。命令耗时不是整个项目耗时，未采集到的 token 不能编数。

10

常见问题

遇到阻塞时，先看安装报告或项目当前状态，再处理真正失败的环节。

安装失败了怎么办？

打开安装目录中的 install-logs/install-report.json，看 errors 与最后一个步骤。网络、WinGet 或权限问题解决后，重复运行同一行安装命令。不要把 incomplete 当作安装完成。

没有 GitHub 账号能用吗？

可以。仓库公开，一行命令直接下载；但 Codex 桌面应用和其账号登录仍需自行准备。

为什么 Codex 还要我确认三次？

思路、分镜和完整预览是不同成果。确认点保证后续成片与自己看过的版本一致。你可以在某条片明确授权直接交付，但不能把一次确认自动沿用到别的片。

要把所有中间素材都用进去吗？

不用。根据口播内容选空间、细节和人物镜头，并检查起落镜抖动与相邻话题重复画面。

字幕或重点字跟不上口播怎么办？

告诉 Codex 具体时间和词。它应检查真实词时间，再调整字幕/主字与音效；不能按字数比例猜时间，也不能让重点字先于口播出现。

封面改了，整条视频都要重做吗？

通常不需要。封面可单独更新并检查版式与安全区；若视频本身没变，应复用原视频。若改的是混音，则复用已核验画面。

导出的 EDL 能直接拿到剪映打开吗？

不能。它是本流程的 JSON 剪辑数据和可追溯工程，不是剪映、Premiere 或 DaVinci Resolve 的原生工程文件。
