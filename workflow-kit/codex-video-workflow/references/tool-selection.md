# 本流程的工具分工

目标是剪用户现有拍摄素材、学习可选参考片，并在思路、分镜和预览处取得用户确认。
下表是该目标下的默认选择，不按 Star 数或“每步换一个项目”选择工具。

| 工作 | 默认选择 | 负责的结果 | 启用条件或边界 |
| --- | --- | --- | --- |
| 内容判断、导演与沟通 | Codex | 理解需求、选镜、叙事、审美、关键内容检查 | 全程；软件检测不能代替判断 |
| 素材盘点 | FFprobe + FFmpeg + Pillow | 清单、时长/画幅/音轨、真实关键帧索引 | 全程；抽样索引不代表完整理解 |
| 参考片拆解 | Hypit 官方 Skill + 本地 media CLI + Codex | 时间码证据、变化候选、逐帧关键区间、结构与自有素材映射 | 有参考视频时；语义由 Codex 根据证据解释 |
| 口播转写 | 优先 Hypit WhisperX | 一份来源清楚、可复用的逐词转写 | 有口播且需要精确选词或字幕时；服务尚需配置和短样验证 |
| 转写备选 | ElevenLabs Scribe 等 | 在首选不适合时提供同类逐词证据 | 按效果、硬件、上传与费用条件选择；不同时无条件重复转写 |
| 剪辑思路与工程 | Codex + video-use | 结构、选段、节奏、EDL、字幕和声音计划 | 思路由用户确认 |
| 关键内容分镜 | FFmpeg + Pillow + 本地 HTML 工具 | 真实截图、源/成片时码、关键内容、文案、声音、覆盖清单 | 思路确认后；用户确认分镜 |
| 系列封面 | FFmpeg 取帧；内置 imagegen 按需生成/编辑；原生版式准确排字 | 同系列 PNG/JPG、准确标题/Logo、可继续修改的设计源文件 | 思路确定方向，分镜确认后制作，随完整预览一起确认 |
| 实际切剪和画面处理 | video-use + FFmpeg | 分段处理、拼接、基础调色、缩放与画幅标准化 | 超出当前后端的变速/转场等先实现并验证，再确认分镜 |
| 字幕 | Codex 校对与断句 + FFmpeg/libass | 时间对齐、中文样式、安全区与最终烧录 | 使用真实转写或用户提供并核实的文案；需要程序动画才追加动效引擎 |
| 声音 | FFmpeg + music.py | 原声、背景音乐、淡入淡出与响度处理 | 当前 music 为固定背景增益；复杂配音/自动闪避另做确定的处理 |
| 完整预览 | 同一EDL + video-use/FFmpeg + efficient.py | 最终质量1920长边内部母版及1280长边完整审片版 | 字幕、音乐与主要动效齐备；集中检查后与封面一起确认 |
| 终稿交付 | efficient.py校验并复制母版 | 与已审预览对应的1920长边MP4、已审封面 | 预览确认后；相同字节复用检查，历史项目无母版才重新渲染 |

## Remotion 是否需要

Remotion 能用 React 制作和渲染视频，但本流程的基础切剪、字幕烧录、混音和编码已由现有后端承担，
所以它是按需引擎，不是每条视频的必经步骤。当前无需把普通字幕、分镜或预览迁移给 Remotion。

同一动效按实际表达方式选择：

1. 普通字幕、静态标题、裁切、缩放和基础滤镜：直接 FFmpeg。
2. 新建 HTML/CSS 图文动画、品牌片头、数据卡片或网页演示：优先考虑 HyperFrames。
3. 已有 React/Remotion 模板，或 React 可复用组件、复杂状态和参数化批量视频更合适：选择 Remotion。
4. 用户已有 Hypit 原生 SVML 工程或明确要求 Hypit 制作该表达时，可沿用它自己的组件体系，不强制再套一层动效引擎。

HyperFrames 与 Remotion 通常是同一动效的二选一，不是连续必经步骤。决定在思路中说明，
分镜确认前验证关键效果能实现；预览确认后不再悄悄更换引擎、资产或表达。
已安装的工具不代表新项目动效已完成；现有 demo 启动器不直接作为新视频工程。

## 思路中的工具记录

在已有 strategy.md 中用几句说明：转写结果与来源、是否需要动效、选哪个引擎及用途、
画幅/音轨标准化、复杂转场或变速的实现路径、当前尚缺的资产或服务。
不新增一个强制用户审批环节；把这些取舍一起放在原来的思路确认中。
